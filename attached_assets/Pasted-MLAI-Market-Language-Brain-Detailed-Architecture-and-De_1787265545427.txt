MLAI Market Language Brain
Detailed Architecture and Development Plan
Document type: Scientific and engineering roadmap  
Project: MLAI — Market Language AI  
Status: Planning document  
Scope: Architecture, data, learning, validation, reasoning, and future live operation  
Code changes: None required by this document
---
1. Executive goal
MLAI should eventually receive:
OHLCV market data
Instrument
Timeframe
Historical context
Any other available market information
and produce an evidence-based explanation of the current market state.
The desired output is not:
```text
Pattern = BUY
Pattern = SELL
```
The desired output is:
```text
Observation
→ sequence interpretation
→ market structure
→ context and regime
→ comparable historical situations
→ historical outcome distribution
→ probability and uncertainty
→ alternative scenarios
→ confirmation conditions
→ invalidation conditions
→ explanation in human language
```
Example target behavior:
> “The short-term market is recovering inside a larger bearish structure. The latest candles show rejection of lower prices, but price has not yet broken the previous significant swing high. Similar historical situations produced mixed outcomes. The current evidence moderately supports a continued recovery, but a close below recent support would weaken that interpretation.”
This system must describe what the data supports. It must not invent hidden orders, trader intentions, certainty, or evidence that is not present.

Market-representation experiments
Causal market-structure experiments through v3.8.6
Sequence and context experiments through v3.9.0

The strongest existing foundations are:

Candle normalization in newer experiments
Chronological validation
Walk-forward validation
Causal swing confirmation
Structural-event detection
ATR-normalized movement outcomes
MFE and MAE analysis
Sequence representation
Permutation/null-testing ideas
Explicit warnings against treating historical evidence as certainty
The main gaps are:
No canonical architecture
No stable shared data contract
No single authoritative research pipeline
No complete historical similarity engine
No validated experience-retrieval layer
No complete probability-calibration layer
No scenario reasoning system

No safe continuous-learning loop
No live-data pipeline
No final unseen-chart generalization system
The existing project should be evolved, not destroyed. Historical versions should be preserved for comparison, while a new controlled research architecture is built around the valid parts.

3. Non-negotiable scientific rules
These rules apply to every future phase.
3.1 Evidence is not certainty
Historical repetition increases or decreases evidence. It does not guarantee repetition.
3.2 Patterns are descriptions, not automatic signals
A hammer, engulfing pattern, BOS, CHoCH, or chart pattern must never directly mean BUY or SELL.
Every observation must be interpreted with:
Prior movement
Location
Structure
Volatility
Momentum
Regime
Confirmation
Failure behavior
3.3 No invisible facts
Without order-book or market-depth data, MLAI must not claim:
Hidden orders
Exact institutional activity
Stop locations
Exact buyer intent
Exact seller intent
Use language such as:
> “Price behavior suggests rejection of lower prices.”
Do not use:
> “Institutions are definitely buying.”
3.4 Causality must be explicit
Every feature needs a known availability time. A feature may only be used after the market data required to calculate it would have existed.
3.5 Future outcomes are targets only
Future returns, future highs, future lows, MFE, MAE, and future structural events must never be inputs to the state being evaluated.
3.6 The final test must remain untouched
The locked test period must not be used to:
Select features
Adjust thresholds
Select models
Change the representation
Tune explanations
Decide what to promote
3.7 Accuracy is not the main success measure
MLAI must prioritize:
Calibration
Generalization
Stability
Uncertainty quality
Evidence traceability
Scenario quality
Robustness across regimes
---
4. Target architecture
The completed system should contain these layers:
```text
1. Data collection
2. Raw immutable storage
3. Data validation and normalization
4. Feature and market-state representation
5. Sequence and event understanding
6. Structure and context engine
7. Historical experience memory
8. Similarity retrieval
9. Outcome and probability engine
10. Scenario reasoning
11. Explanation generation
12. Delayed outcome evaluation
13. Controlled knowledge updating
14. Validation and monitoring
```
These layers must remain separate.
In particular:
```text
Data collection ≠ Learning
Learning ≠ Validation
Validation ≠ Inference
Inference ≠ Knowledge promotion
```

11. Phase P0/P1 — Repair the validation methodology
Purpose
Ensure that apparent learning is not the result of selection bias, leakage, or repeated experimentation.
What will be added
Chronological splits
```text
Training period
→ validation period
→ locked final test period
```
Walk-forward validation
Use expanding or rolling windows with fixed, recorded boundaries.
Purging
Remove training observations whose outcome windows overlap the validation period.
Embargo
Leave a time gap around validation boundaries where necessary.
Pre-registered experiments
Before running an experiment, record:
Hypothesis
Data version
Feature version
Target
Horizons
Candidate rules
Candidate models
Primary metric
Secondary metrics
Acceptance threshold
Null and permutation testing
The null test must:
Keep feature representation fixed
Shuffle only valid target labels
Preserve fold boundaries
Preserve the observed selection procedure
Compare equivalent statistics
Report the number of candidate rules
Report the maximum-null distribution
Account for multiple testing
Required v3.4.2 investigation
The unusually high best-null-rule result must be investigated before trusting later rule-discovery claims.
The investigation must check:
Class imbalance
Baseline correctness
Number of tested rules
Maximum-of-many selection
Horizon overlap
Label leakage
Fold leakage
Quantile-boundary leakage
Incorrect null aggregation
Reuse of validation results
Gate to continue
The validation system must show that:
Results beat a correctly defined baseline
Results remain stable across chronological windows
Results survive a locked test
Null results behave as expected
Selected rules are not simply the best result from a huge search

17. Phase P2 — Multi-timeframe reasoning
Purpose
Understand that short-term movement can occur inside an opposing higher-timeframe structure.
What will be added
Each timeframe will have its own:
Candle history
Structure
Regime
Sequence state
Support/resistance
Confirmation timing
The combined context may look like:
```text
Weekly: bearish
4H: bearish-to-neutral
1H: recovery
5M: bullish impulse
```
The explanation must understand:
```text
5M recovery ≠ higher-timeframe reversal
```
Requirements
Correct timestamp synchronization
No use of incomplete higher-timeframe candles
Independent causality checks per timeframe
Separate feature histories
Explicit timeframe conflict handling
Gate to continue
The system must explain disagreements between timeframes instead of collapsing them into one direction.

24. What must not be done
Do not:
Optimize only for historical accuracy
Treat a stored pickle as proof of learning
Treat a pattern as a trade signal
Use future-confirmed structure before it is available
Reuse the final test period
Repeatedly alter rules until a desired result appears
Compare one observed rule against the best of thousands of null rules without correcting selection
Claim hidden liquidity without market-depth data
Claim trader intent from OHLCV alone
Add online learning before delayed validation exists
Replace the entire current project without first preserving useful components
Promote a result that does not beat a correct baseline

26. Final verdict and path forward
The current MLAI project has useful foundations, especially in:
Causal structure
Sequence representation
Chronological validation
Historical experimentation
It does not yet contain the complete Market Language Brain.
The largest missing components are:
Unified representation
Valid historical experience retrieval
Calibrated probability
Scenario reasoning
Generalization testing
Controlled knowledge updating
Reliable live-data separation
The shortest scientifically valid path is:
```text
Audit
→ protect
→ normalize data
→ enforce causality
→ represent market language
→ validate chronologically
→ retrieve historical experience
→ calibrate probability
→ reason through scenarios
→ explain evidence
→ test unseen charts
→ add controlled learning
→ connect live data
```
This roadmap is intended to achieve the stated goal through staged, measurable work. Each phase must prove its reliability before the next layer is trusted.
